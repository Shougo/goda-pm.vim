==============================================================================
INTRODUCTION                                            *goda-pm-introduction*

goda-pm.vim is the successor of dpp.vim on goda.vim: a plugin manager whose
protocols and exts are Go, in a binary built from your configuration
(main.go), and Vim talks to it through goda.vim.  There is no Deno.

The startup does not use the binary: as dpp.vim, goda-pm writes a state
(a startup script and the plugins) once, and |goda_pm#min#load_state()|
sources it.  The binary is needed to make the state and to install and
update the plugins.

The TOML files of dpp-ext-toml work as they are.

==============================================================================
INSTALL                                                      *goda-pm-install*

It needs Vim 9.1 or Neovim 0.11, Go 1.26, git and goda.vim 0.7 or later:

https://github.com/Shougo/goda.vim

goda.vim is needed only to make the state and to run the exts: it must be in
'runtimepath' then (a plugin that is not lazy, or added by your vimrc).

CONFIGURATION                                          *goda-pm-configuration*

The configuration is a Go module in |g:goda_pm#config_dir|: a main.go that
adds the protocols and the exts (|goda-pm-exts|), and gives the plugins
(examples/config has one, which loads TOML files and the plugins of ~/work):
>go
	import (
		"github.com/Shougo/goda-pm-ext-lazy.vim/ext/lazy"
		"github.com/Shougo/goda-pm-ext/ext/installer"
		"github.com/Shougo/goda-pm-ext/ext/protocol/git"
		"github.com/Shougo/goda-pm-ext/ext/protocol/http"
		"github.com/Shougo/goda-pm-ext/ext/toml"
		"github.com/Shougo/goda-pm.vim/pm"
	)

	func main() {
		b := pm.New()
		b.AddProtocol(git.New())
		b.AddProtocol(http.New())
		b.AddExt(installer.New())
		b.SetConfig(config)
		b.Main()
	}

	func config(ctx context.Context, c *pm.ConfigArgs) (
			*pm.ConfigReturn, error) {
		c.Options.InlineVimrcs = []string{"$BASE_DIR/options.rc.vim"}
		t, err := toml.Load(
			ctx,
			c.Host,
			"$BASE_DIR/dpp.toml",
			pm.Plugin{"lazy": false},
		)
		if err != nil {
			return nil, err
		}
		r, err := lazy.MakeState(ctx, c.Host, t.Plugins)
		if err != nil {
			return nil, err
		}
		return &pm.ConfigReturn{
			Plugins:    r.Plugins,
			StateLines: r.StateLines,
			Ftplugins:  t.Ftplugins,
		}, nil
	}
<
The configuration runs when the state is made (|goda_pm#make_state()|),
in the binary: ConfigArgs has the editor (Host: has(), expand() and the
environment of the editor, as $BASE_DIR set by the vimrc), the base
directory, and the options it sets (|goda-pm-options|).  It gives
ConfigReturn: the plugins (a pm.Plugin is the dictionary of a plugin, as
those of the TOML files), and CheckFiles, Ftplugins, Groups, HooksFiles,
MultipleHooks and StateLines, as dpp.vim's.

|goda_pm#make_state()| builds the configuration when it is newer than the
binary; |goda_pm#build()| builds it.

g:goda_pm#config_dir                                    *g:goda_pm#config_dir*
		The configuration module.
		Default: "~/.vim/goda-pm", Neovim: stdpath('config') .
		'/goda-pm'

g:goda_pm#binary                                            *g:goda_pm#binary*
		The binary.  When it is set, it is yours to build: it is not
		built.
		Default: goda-pm in the cache directory ("~/.cache/vim/goda-pm",
		Neovim: stdpath('cache') . '/goda-pm')

STARTUP                                                      *goda-pm-startup*

Clone goda-pm.vim, goda.vim and goda-pm-ext-lazy.vim where the protocol git
puts them (list them in your TOML files too, not lazy, and they are updated
as the others):
>sh
	git clone https://github.com/Shougo/goda-pm.vim \
	  ~/.cache/goda-pm/repos/github.com/Shougo/goda-pm.vim
	git clone https://github.com/Shougo/goda.vim \
	  ~/.cache/goda-pm/repos/github.com/Shougo/goda.vim
	git clone https://github.com/Shougo/goda-pm-ext-lazy.vim \
	  ~/.cache/goda-pm/repos/github.com/Shougo/goda-pm-ext-lazy.vim
<
The vimrc, as dpp.vim's:
>vim
	" goda-pm.vim must be in 'runtimepath'.
	set runtimepath^=~/.cache/goda-pm/repos/github.com/Shougo/goda-pm.vim

	const s:base = '~/.cache/goda-pm'
	let $BASE_DIR = '<script>:h'->expand()

	if s:base->goda_pm#min#load_state()
	  " No state (or it is old): goda.vim and goda-pm-ext-lazy.vim are
	  " needed to make it.
	  set runtimepath^=~/.cache/goda-pm/repos/github.com/Shougo/goda.vim
	  set runtimepath^=~/.cache/goda-pm/repos/github.com/Shougo/goda-pm-ext-lazy.vim
	  autocmd VimEnter * ++once call goda_pm#make_state(s:base)
	endif

	autocmd User GodaPm:makeStatePost
	      \ echomsg 'goda_pm#make_state() is done; restart Vim'

	filetype plugin indent on
	syntax on
<
After the state is made, restart Vim, and install the plugins:
>vim
	call goda_pm#async_ext_action('installer', 'install')
<
The state is made again when the files it was made from change:
>vim
	autocmd BufWritePost *.toml,*.vim,*.go
	      \ : if !goda_pm#check_files()->empty()
	      \ |   call goda_pm#make_state()
	      \ | endif
<
The state sets |g:goda#workspace| of goda.vim to the directories of the
plugins that are Go modules: |goda#build()| (the build() of the goda.vim
plugins) builds their binaries with the plugins installed (and those of a
local directory), not with the versions their configurations require.
After an update, build them again, with no "go get -u":
>toml
	[[plugins]]
	repo = 'Shougo/goda-fi.vim'
	hook_post_update = 'call goda_fi#build()'
<

OPTIONS                                                      *goda-pm-options*

The configuration sets them (c.Options, of pm.Options).

                                                    *goda-pm-option-extParams*
ExtParams	(map[string]pm.Params)
		It is a dictionary that maps ext names to its parameters.
		See also |goda-pm-ext-attrs| and the documentation of the
		ext.
		Default: {}

                                              *goda-pm-option-hooksFileMarker*
HooksFileMarker	(string)
		The marker is used in |goda-pm-plugin-option-hooks_file|:
		the start and the end of a hook.
		Default: "{{{,}}}"

                                                 *goda-pm-option-inlineVimrcs*
InlineVimrcs	(string list)
		The vimrcs are sourced in |goda_pm#min#load_state()| before
		hooks: they are put in the startup script.
		NOTE: The files must not be included "<<" pattern (here
		document).  It breaks the parser.
		NOTE: It also supports ".lua" file for Neovim.
		Default: []

                                               *goda-pm-option-protocolParams*
ProtocolParams	(map[string]pm.Params)
		It is a dictionary that maps protocol names to its
		parameters.  See also the documentation of the protocol.
		Default: {}

                                                    *goda-pm-option-protocols*
Protocols	(string list)
		The protocols that detect the plugins, in order.
		Default: all the protocols added, in the order they were

                                     *goda-pm-option-skipMergeFilenamePattern*
SkipMergeFilenamePattern	(string)
		It is the pattern of skip filename when
		|goda-pm-plugin-option-merged| is set (|goda-pm-merge|).
		NOTE: It must be Go regexp.
		NOTE: It is only effective for files directly under the
		directory.
		Default: '^tags(?:-\w\w)?$|^package\.json$|\.md$'

PLUGIN OPTIONS                                        *goda-pm-plugin-options*

		The plugin options are those of dpp.vim: the keys of a plugin
		in the TOML files (toml.Load() of goda-pm-ext), or of
		pm.Plugin in the configuration.  It accepts the following
		keys:

                                               *goda-pm-plugin-option-augroup*
augroup		(string)
		An augroup name that the plugin uses for |VimEnter| or
		|GUIEnter| autocmd events.

                                               *goda-pm-plugin-option-depends*
depends		(list or string)
		Specify a list of plugins a plugin depends on.
		List items are '{plugin-name}'.
		Those specified in the list are NOT installed automatically.
		NOTE: The loading order is not guaranteed in non-lazy plugins.

                                           *goda-pm-plugin-option-description*
description	(string)
		Describe the plugin.

                                              *goda-pm-plugin-option-extAttrs*
extAttrs	(dictionary)
		It is a dictionary that exts specific attributes.
		See also |goda-pm-ext-attrs|.

                                     *goda-pm-plugin-option-external_commands*
external_commands (list) or (string)
		It is external commands dependency.
		If the commands are not |executable()|, the plugin is ignored.

                                              *goda-pm-plugin-option-ftplugin*
ftplugin	(dictionary)
		"_" key is executed after all ftplugin.
		"{filetype}" key is executed {filetype} ftplugin.
		"lua_{filetype}" key is executed {filetype} ftplugin as
		|:lua|.
		You can define multiple filetypes by "{filetype1}_{filetype2}"
		key.  "b:undo_ftplugin" is defined automatically.
		NOTE: The state must be made again after it is changed (see
		|goda_pm#check_files()|).
		NOTE: It is not executed when the plugin is not installed.

                                                 *goda-pm-plugin-option-group*
group		(list) or (string)
		It is group name.

                                                    *goda-pm-plugin-option-if*
if		(bool) or (string)
		If set to |v:false|, goda-pm doesn't load the plugin.
		If it is |String|, goda-pm will eval it.
		If you don't set it, goda-pm will register (enable) the
		plugin.
		NOTE: You cannot disable plugins register in goda-pm if you
		use the option.

                                                  *goda-pm-plugin-option-lazy*
lazy		(bool)
		If set to v:true, goda-pm doesn't add the path to
		'runtimepath' automatically.
		If you don't set it, goda-pm will set it automatically when
		the conditions are met.
		NOTE: You should not specify the plugins which have no
		"plugin/" directory as lazy load plugins.  It is meaningless
		and just increases the overhead.
		NOTE: To load lazy plugins, you need goda-pm-ext-lazy.vim
		(|goda-pm-exts|).

                                                 *goda-pm-plugin-option-local*
local		(bool)
		If set to v:true, it is local installed plugin.

                                                *goda-pm-plugin-option-merged*
merged		(bool)
		If set to v:false, goda-pm doesn't merge the plugin
		directory.
		It is useful for the plugin files conflicts.

		Default: See |goda-pm-merge|.

                                        *goda-pm-plugin-option-merge_ftdetect*
merge_ftdetect	(bool)
		If set to v:true, goda-pm merge the plugin "ftdetect"
		directory.
		It is useful to enable file detection when lazy loaded plugin.
		NOTE: It does not work if ftdetect script depends on lazy
		plugin functions.

                                                  *goda-pm-plugin-option-name*
name		(string)
		Specify the name of the plugin.  This is used for goda-pm
		management and other functions.  If it is omitted, the tail of
		the repository name will be used.
		NOTE: Must be unique across the all plugin.  If the repo tail
		is bound to conflict, you can set the "name" option manually
		to prevent overwriting an existing plugin setting.

                                                *goda-pm-plugin-option-on_cmd*
on_cmd		(list) or (string)
		If it matches the executed command name, goda-pm will call
		|goda_pm#source()|.
		NOTE: It must be unique.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                              *goda-pm-plugin-option-on_event*
on_event	(string) or (list)
		goda-pm will call |goda_pm#source()| on the events.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                               *goda-pm-plugin-option-on_func*
on_func		(list) or (string)
		If it matches the called undefined function name, goda-pm
		will call |goda_pm#source()|.
		NOTE: It does not work when Vim initialized.
		NOTE: It does not work for Vim9 script.  It is
		|FuncUndefined| limitation.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                                 *goda-pm-plugin-option-on_ft*
on_ft		(list) or (string)
		If it matches 'filetype', goda-pm will call
		|goda_pm#source()|.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                                 *goda-pm-plugin-option-on_if*
on_if		(string)
		If it evaluates to a non-zero value, goda-pm will call
		|goda_pm#source()|.
		The default evaluate timings are "BufRead", "BufNewFile",
		"VimEnter" and "FileType".
		If |goda-pm-plugin-option-on_event| exists, it is evaluated
		when |goda-pm-plugin-option-on_event|.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                                *goda-pm-plugin-option-on_lua*
on_lua		(list) or (string)
		If it matches the required lua module root, goda-pm will call
		|goda_pm#source()|.
		NOTE: It is for Neovim only.
		NOTE: It does not work for Neovim standard modules and require
		in |vim.loop| modules.
		NOTE: You cannot require on_lua plugins in
		|goda-pm-plugin-option-hook_add|.  Because the plugins are not
		initialized.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                                *goda-pm-plugin-option-on_map*
on_map		(Dictionary) or (list) or (string)
		If it is the Dictionary, the key is {mode} and the items are
		{mapping} or [{mapping1}, {mapping2}, ...].
		If it is the List, the items are {mapping} or [{mode},
		{mapping1}, [{mapping2}, ...]].
		If {mode} is omitted, "nxo" is used.
		NOTE: You can use plugin prefix mappings.
		For example, you can use "<Plug>(ref-" instead of
		"<Plug>(ref-back)" and so on.
		NOTE: It must be unique.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                               *goda-pm-plugin-option-on_path*
on_path		(list) or (string)
		If set to ".*", goda-pm will call |goda_pm#source()| on
		editing all files.  Otherwise, goda-pm will call
		|goda_pm#source()| if the buffer name is matched to the string
		pattern.
		NOTE: It is useful for explorer behavior plugins.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                        *goda-pm-plugin-option-on_post_source*
on_post_source	(list) or (string)
		Load the plugin after the listed plugins are loaded.
		NOTE: The plugins must be lazy loaded plugins.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                               *goda-pm-plugin-option-on_root*
on_root		(list) or (string)
		Load the plugin when current directory has specified root
		files.
		It is useful to load project specific plugins.
		NOTE: It must be a file rather than a directory.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                             *goda-pm-plugin-option-on_source*
on_source	(list) or (string)
		Load the plugin before the listed plugins are loaded.
		NOTE: The plugins must be lazy loaded plugins.
		NOTE: To use the feature, you need goda-pm-ext-lazy.vim.

                                                  *goda-pm-plugin-option-path*
path		(string)
		Specify the plugin downloaded path.
		If it is not an absolute path, it is converted to under the
		plugin "base-path".
		NOTE: It is set by protocol.

		Default:
		If it is not set, it will be error.

                                              *goda-pm-plugin-option-priority*
priority	(Number)
		Plugin load priority.

                                              *goda-pm-plugin-option-protocol*
protocol	(string)
		User specified protocol.

                                         *goda-pm-plugin-option-protocolAttrs*
protocolAttrs	(Dictionary)
		It is a dictionary that protocols specific attributes.
		See also |goda-pm-protocol-attrs|.

                                                  *goda-pm-plugin-option-repo*
repo		(string)
		Specify the plugin repository.

                                                   *goda-pm-plugin-option-rev*
rev		(string)
		Specify a revision number or branch/tag name.
		If it is "*" in "git" protocol, goda-pm will use latest
		released tag.  You can specify the wildcards like "0.*".
		NOTE: In "http" protocol, it is the SHA-1 of what is
		downloaded.

                                                   *goda-pm-plugin-option-rtp*
rtp		(string)
		Specify the runtime path.
		You can use it when the repository has the Vim plugin in a
		subdirectory.
		For example: https://github.com/rstacruz/sparkup
		If it is empty string, goda-pm will not add the path to
		'runtimepath'.  It is useful to manage non-plugin repositories
		or already added to 'runtimepath' plugin manually.
		NOTE: If it is empty string,
		|goda-pm-plugin-option-hook_source| and
		|goda-pm-plugin-option-hook_post_source| hooks are not called.

		Default: Same as |goda-pm-plugin-option-path|.

                                           *goda-pm-plugin-option-script_type*
script_type	(string)
		Specify the script type.  It is useful for non-official
		categorized plugins.
		For example: "indent", "plugin", "ftplugin", ...
		NOTE: You must not specify it for categorized plugins.

                                                   *goda-pm-plugin-option-url*
url		(string)
		Specify the webpage URL.
		NOTE: It is set by protocol.

HOOKS                                                          *goda-pm-hooks*

		The string is split into lines.
		It is useful for the plugins initialization.

		NOTE: The loading order is not guaranteed in non-lazy plugins.
		NOTE: The string is executed as Ex commands.

		You can use |Vim9| script for hooks.  But you cannot use
		|Vim9| script in global |goda-pm-plugin-option-hook_add|.
		Because it may be merged for optimize.

		To use |Vim9| script, you need to use |:vim9script| or |:def|.
		NOTE: |Vim9| script syntax is very strict and it is hard to
		debug.  It is experimental feature.

		The arguments of the hook are |g:goda_pm#hook_args|.
		To return a value from a hook, assign it to
		|g:goda_pm#hook_result|.  The variable is reset to |v:null|
		before each hook execution.
>vim
		hook_source = '''
		  let g:goda_pm#hook_result = s:configure()
		'''
<
                                            *goda-pm-plugin-option-hooks_file*
hooks_file	(string) or (list)
		Hooks file path.  It must be valid path.
		It is useful to define long hooks.

		The file format is:

		{hook_name} {start_marker}
		...
		{end_marker}

		{start_marker} and {end_marker} are from
		|goda-pm-option-hooksFileMarker|.
		{hook_name} is "hook_xxx" or "lua_xxx" or
		|goda-pm-plugin-option-ftplugin| filetype.

		Example:
>vim
		" hook_source {{{
		let g:foo = 'bar'
		" }}}
		" cpp {{{
		let g:bar = 'baz'
		" }}}
		" Use vim9script
		" hook_update {{{
		vim9script
		g:bar = 'baz'
		" }}}
<
                                              *goda-pm-plugin-option-hook_add*
hook_add	(string)
		It is executed after the plugin is added.
		It is mainly used for defining mappings.
		NOTE: You cannot call plugin function in "hook_add".
		Because the plugin is not sourced when "hook_add".
		NOTE: It is not executed when the plugin is not installed.
		It is executed when the plugin is installed, before
		|goda-pm-plugin-option-hook_post_update| (the installer of
		goda-pm-ext): what the hooks of the plugin use, set by it,
		is set then.

                                   *goda-pm-plugin-option-hook_depends_update*
hook_depends_update (string)
		It is executed after |goda-pm-plugin-option-depends| plugins
		are updated.
		NOTE: To use the feature, you need the installer of
		goda-pm-ext (|goda-pm-exts|).

                                      *goda-pm-plugin-option-hook_done_update*
hook_done_update (string)
		It is executed after plugins are updated.
		NOTE: To use the feature, you need the installer of
		goda-pm-ext.

                                      *goda-pm-plugin-option-hook_post_source*
hook_post_source (string)
		It is executed after the plugin script files are sourced.
		It does not work for non-lazy plugins.
		NOTE: |goda-pm-plugin-option-rtp| must not be empty string.

                                *goda-pm-plugin-option-hook_post_check_update*
hook_post_check_update (string)
		It is executed after checking for updates.
		If it set |g:goda_pm#hook_result| to |v:true|, the update
		will be skipped.
		It is useful to check updated result.

		args (|g:goda_pm#hook_args|):
			{oldRev}: Current revision.

			{newRev}: Updated revision.

			{plugin}: Plugin dictionary.

		NOTE: The plugin may not be sourced.
		NOTE: To use the feature, you need the installer of
		goda-pm-ext.

                                      *goda-pm-plugin-option-hook_post_update*
hook_post_update (string)
		It is executed after updated and before the build of the
		installer (its "build" action, and extAttrs.installerBuild).
		NOTE: The plugin may not be sourced.
		NOTE: To use the feature, you need the installer of
		goda-pm-ext.

                                       *goda-pm-plugin-option-hook_pre_update*
hook_pre_update (string)
		It is executed before updated.
		NOTE: The plugin may not be sourced.
		NOTE: To use the feature, you need the installer of
		goda-pm-ext.

                                           *goda-pm-plugin-option-hook_source*
hook_source	(string)
		It is executed after plugin runtimepath is added and before
		the plugin script files are sourced.
		It also works for non-lazy plugins.
		It is mainly used for plugin configure.
		NOTE: The "sourced" means after |goda_pm#min#load_state()| or
		autoloaded.
		NOTE: |goda-pm-plugin-option-rtp| must not be empty string.

                                               *goda-pm-plugin-option-lua_xxx*
lua_xxx		(string)
		Lua language string hook instead of Vim script.
		It is converted to "hook_xxx" key.

PLUGINS MERGED FEATURE                                         *goda-pm-merge*

goda-pm.vim copies the files of multiple plugins into a single directory and
loads them as plugins by default.  It expects to improve performance.

That path is `{base-path}/{name}/.goda_pm`.

Other plugin managers add a plugin path into 'runtimepath' to load external
plugins.  However, if the 'runtimepath' is very large then it will load
slowly.  This is because Vim needs to find and load all 'runtimepath' to load
plugins.  In goda-pm.vim, this problem does not exist.

The following plugins will not be merged to prevent merge problems
- |goda-pm-plugin-option-merged| is v:false
- local plugin (|goda-pm-plugin-option-local|, local.Load() of goda-pm-ext)
- lazy loaded plugin (|goda-pm-plugin-option-lazy|)
- uses |goda-pm-plugin-option-hook_post_update|
- uses |goda-pm-plugin-option-if|

The files of |goda-pm-option-skipMergeFilenamePattern| are not merged.

EXT ATTRS                                                  *goda-pm-ext-attrs*

There are the ext specific attributes for items (extAttrs).  Please read the

FUNCTIONS                                                  *goda-pm-functions*

                                                    *goda_pm#min#load_state()*
goda_pm#min#load_state({base-path}[, {name}])
		Load the state of {name} (|v:progname| without its extension
		by default: vim or nvim) in {base-path}.  It returns 1 when
		there is none, or it cannot be loaded: then make it with
		|goda_pm#make_state()|.

                                                        *goda_pm#make_state()*
goda_pm#make_state([{base-path}[, {name}[, {extra-args}]]])
		Make the state in the background: the configuration runs.
		|GodaPm:makeStatePost| is done after it.  It builds the
		configuration first when it is newer than the binary.
		{base-path} is that of |goda_pm#min#load_state()| by default.
		{extra-args} is ConfigArgs.ExtraArgs.

                                                   *goda_pm#make_state_sync()*
goda_pm#make_state_sync([{base-path}[, {name}[, {extra-args}]]])
		As |goda_pm#make_state()|, and wait for it.

                                                       *goda_pm#clear_state()*
goda_pm#clear_state([{name}])
		Remove the state.

                                                       *goda_pm#check_files()*
goda_pm#check_files([{base-path}[, {name}]])
		The files of the state (CheckFiles, the inline vimrcs, the
		hooks files and the configuration) that are newer than it.

                                                       *goda_pm#check_clean()*
goda_pm#check_clean()
		The directories of the plugins in {base-path}/repos that are
		not in the state.

                                                               *goda_pm#get()*
goda_pm#get([{name}])
		The plugin {name}, or all of them.
		NOTE: What only |goda_pm#make_state()| uses is not in them:
		"hook_add" (run by the startup script; that of a plugin not
		installed is, for its installation), "ftplugin" (in the
		ftplugin files of the merged plugins) and the "lua_" hooks
		(the "hook_" ones run them).

                                                            *goda_pm#source()*
goda_pm#source([{plugins}[, {function-prefix}]])
		Load the plugins (names or dictionaries), or all of them.

                                                   *goda_pm#sync_ext_action()*
goda_pm#sync_ext_action({ext}, {action}[, {params}])
		Run the action of the ext, and give its result.  Long ones
		(install, update) can be run so in a script: >sh
		vim -N -u ~/.vimrc -c "call goda_pm#sync_ext_action(
		  \ 'installer', 'update')" -c 'qall!'
<
                                                  *goda_pm#async_ext_action()*
goda_pm#async_ext_action({ext}, {action}[, {params}])
		Run the action of the ext in the background.

                                                              *goda_pm#exts()*
goda_pm#exts()
		The exts of the binary and their actions: {ext: [action]}.

                                                             *goda_pm#build()*
goda_pm#build()
		Build the configuration into |g:goda_pm#binary|, with
		|goda#build()| of goda.vim.  The running binary is stopped,
		and the new one starts with the next request.
		NOTE: The binary is built by itself when there is none, the
		configuration is newer, or it is of another version than the
		Vim script (see "build" of |goda#register()|): not one of
		|g:goda_pm#binary| set by you.
		While the binary runs an action or makes the state, the
		build waits for them: hook_post_update of goda-pm.vim can
		call it.
>toml
		[[plugins]]
		repo = 'Shougo/goda-pm.vim'
		hook_post_update = 'call goda_pm#build()'
<

                                                       *goda_pm#toml_syntax()*
goda_pm#toml_syntax()
		Highlight the Vim script and the Lua of the hooks of the
		TOML file of the buffer: >vim
		autocmd BufRead *.toml call goda_pm#toml_syntax()
<		(It was goda_pm#ext#toml#syntax().)
The Lua entry: require('goda_pm') has the functions of goda_pm#*(), and
load_state() is |goda_pm#min#load_state()|:
>lua
	local goda_pm = require('goda_pm')
	if goda_pm.load_state(base) then
	  goda_pm.make_state(base)
	end
<

PROTOCOLS AND EXTS                                              *goda-pm-exts*

The protocols and the exts are in repositories of their own: add them in the
configuration (|goda-pm-configuration|).

goda-pm-ext	https://github.com/Shougo/goda-pm-ext
		Go packages (not a Vim plugin): the protocols git
		(ext/protocol/git, dpp-protocol-git) and http
		(ext/protocol/http, dpp-protocol-http), the ext installer
		(ext/installer, dpp-ext-installer), toml.Load() (ext/toml,
		dpp-ext-toml), local.Load() (ext/local, dpp-ext-local) and
		the source "goda_pm" of goda-fi.vim (ext/fi/pmfi,
		ddu-source-dpp).  Its README has their params.

goda-pm-ext-lazy.vim
		https://github.com/Shougo/goda-pm-ext-lazy.vim
		lazy.MakeState() (ext/lazy, dpp-ext-lazy): the lazy loading.
		It has Vim script: it must be in 'runtimepath' (see
		|goda-pm-startup|).  |goda-pm-ext-lazy|

==============================================================================
WRITING EXTENSIONS                                        *goda-pm-extensions*

A protocol implements pm.Protocol (embed pm.BaseProtocol for the methods
it does not need), and an ext pm.Ext: its actions get the options of the
state, the protocols and the editor.

==============================================================================
DIFFERENCES FROM DPP                                             *goda-pm-dpp*

- The configuration is Go (main.go), not TypeScript, and there is no Deno:
  the protocols and the exts are Go packages compiled into the binary.
- |goda_pm#make_state()| has no {config-path}: the configuration is the
  binary.  Its files (*.go and go.mod) are checked by
  |goda_pm#check_files()|.
- The names: goda_pm# for dpp#, g:goda_pm for g:dpp, GodaPm: for Dpp: in
  the autocmds, and the runtime directory of the state is .goda_pm.
- toml, local and lazy are Go functions of the configuration, not exts with
  actions.
- The protocol http does not need curl, wget, unzip nor tar.
- packspec is not supported.
- The denops plugins still work: a lazy loaded one is registered to
  denops.vim (when it runs), and the installer has denoCache.
